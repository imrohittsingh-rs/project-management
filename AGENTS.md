
# Project-Wide Agent Instructions

## Mandatory Design Rules

For EVERY frontend-related task, including creating, editing, reviewing, or refactoring UI components, pages, layouts, styles, and responsive behavior:

1. Read the root `DESIGN.md` before making changes.
2. Treat `DESIGN.md` as the authoritative source for visual design decisions.
3. Inspect existing frontend components and styles before implementing anything.
4. Preserve the established theme, design tokens, typography, spacing, and component conventions.
5. Do not introduce a new visual style or redesign unrelated parts of the application.
6. Avoid generic AI-generated UI patterns, unnecessary gradients, excessive animations, fake metrics, and fabricated testimonials.
7. Reuse existing components and dependencies whenever practical.
8. Check responsive behavior and accessibility.
9. Validate the implementation with relevant checks when possible.

## Project References

- `DESIGN.md`: Visual design system and UI standards.
- `PRD.md`: Product requirements and expected behavior.

Read the relevant references before making changes. Never claim to have inspected a file unless you actually read it.
